1. PROJECT PURPOSE
------------------
NeoOrigins Localization is a client-side NeoForge mod/resource-pack system that provides LOW-PRIORITY FALLBACK translations for Neo Origins / NeoOrigins and compatible add-ons.

Core rule:
- Neo Origins / NeoOrigins is the MAIN mod being translated by this project.
- Official upstream translations ALWAYS have priority.
- Our project only fills keys that are missing upstream.
- Normal resource packs can still override translations.
- No translation is generated at runtime in Minecraft.
- When upstream later adds an official translation, our overlapping fallback key must be removed.

The project uses heavy generative/automated translation assistance, with structural audits and human direction. It must not be presented as fully native-speaker-reviewed translation work.

Origin names should only be translated when the result stays natural, identifiable and readable in the UI. Otherwise the English/canonical name may be kept.

5. LANGUAGE EXPANSION RULE FOR 0.9.0
------------------------------------
The goal is NOT to stop at 17 languages. The long-term target is to cover essentially all useful Minecraft languages, except explicitly excluded cases.

CRITICAL RULE ABOUT LANGUAGE VARIANTS:
The English US/UK example was ONLY an example. The same rule applies to EVERY language family.

If Minecraft contains several regional variants of the same language and those variants are nearly identical (for example only one, two or a few words differ), DO NOT translate and maintain each one separately. Keep ONE representative/canonical variant for that language family.

Examples of the principle:
- en_us / en_gb: do not maintain both if the content difference is trivial.
- The same deduplication must be evaluated for Spanish, Portuguese, French, Chinese, or any other language family with regional variants.

Keep multiple variants only if they are genuinely different enough to justify separate localization work: significantly different vocabulary, orthography/script, grammar, terminology, or Minecraft usage.

Do NOT assume a final target locale count in advance. First obtain the current Minecraft locale list, group regional variants, compare real differences, then select the representative set.

A few very marginal/unsuitable locales may be excluded, but this must be a deliberate project decision, not an arbitrary omission.

For every newly added language, the intent is to support that language across NeoOrigins and all compatible/licensed add-ons in the relevant Minecraft target, not only a handful of projects.

9. AUDIT / QA RULES
-------------------
Every project integration and language expansion must preserve these checks:
- valid JSON
- no duplicate keys
- no missing English-source keys that should be covered
- no stale keys unless explicitly documented
- no fallback overlap with upstream official translations
- placeholders preserved exactly, including forms such as %s, %1$s, %2$s, %d, etc.
- correct target packaging
- no 1.21.1-only add-on namespaces accidentally packaged in 26.x
- Java/NeoForge build succeeds for each supported target
- inspect built JAR contents after construction

Existing validation/audit pattern includes:
python scripts/validate.py
python scripts/audit_neoorigins_upstream.py --fail-on-overlap --fail-on-missing
python scripts/audit_medievalorigins_upstream.py --fail-on-overlap --fail-on-missing --fail-on-placeholders
python scripts/audit_ibarnorigins_upstream.py --fail-on-overlap --fail-on-missing --fail-on-placeholders
python scripts/audit_origins_fantasy_upstream.py --fail-on-overlap --fail-on-missing --fail-on-placeholders
