1. PROJECT PURPOSE
------------------
NeoOrigins Localization provides LOW-PRIORITY fallback translations for Neo Origins / NeoOrigins and compatible add-ons.

Core rule:
- Neo Origins / NeoOrigins is the MAIN mod translated by this project.
- Official upstream translations ALWAYS have priority.
- This project fills only missing keys.
- When upstream adds an official translation, overlapping fallback keys must be removed.
- No localization is generated at runtime in Minecraft.
- Automated/generative translation assistance is used heavily, with structural audits and human direction. Do not present the translations as fully native-speaker-reviewed.

8. LANGUAGE EXPANSION RULE
--------------------------
0.9.0 should expand well beyond 20 locales toward essentially all useful Minecraft languages.

Regional-variant rule applies to EVERY language family, not only English:
- If two regional variants differ by only a handful of words, maintain ONE representative locale.
- Keep separate variants when vocabulary, writing/script, grammar, terminology, Minecraft usage, or written standard is materially different.
- Do not assume the final locale count in advance. Compare the current Minecraft locale set first.
- Bokmal (no_no) and Nynorsk (nn_no) are treated as separate written standards, not deduplicated into one locale.

For every selected new language, the intent is to cover NeoOrigins and all compatible/licensed add-ons relevant to that Minecraft target.

10. QA RULES
------------
Always validate:
- JSON validity
- duplicate keys
- missing keys
- overlaps with official upstream translations
- placeholders such as %s, %1$s, %d
- correct target packaging
- no 1.21.1-only add-ons leaking into 26.x
- successful builds
- built JAR contents
- visual/in-game wording and UI width when possible

For a new language, follow the Danish/Finnish/Norwegian/Swedish architecture when a large NeoOrigins translation must be split across resource-pack namespaces. Do not assume one giant locale JSON is appropriate.
